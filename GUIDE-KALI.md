# Руководство по запуску GameHub Security Lab в Kali Linux

## 1. О проекте

GameHub Security Lab — учебное веб-приложение на Python и Flask, предназначенное для демонстрации двух распространённых уязвимостей веб-приложений:

- **SQL Injection (CWE-89)** — внедрение SQL-кода.
- **Path Traversal (CWE-22)** — обход ограничений доступа к файлам.

В проекте представлены две версии приложения:

- `vulnerable` — содержит намеренно оставленные уязвимости.
- `fixed` — содержит исправления обнаруженных уязвимостей.

Цель руководства — показать, как подготовить окружение Kali Linux, запустить приложение, провести учебные проверки и сравнить результаты двух версий.

> **Важно:** все проверки необходимо выполнять исключительно в локальной лабораторной среде. Приложение должно быть доступно только по адресу `127.0.0.1`. Не открывайте уязвимую версию в Интернет или публичную сеть.

Для работы понадобится:

|---|---|


Проверь установку:

```bash

```

## 4. Запуск уязвимой версии

### 4.1. Переход в каталог приложения

```bash
cd ~/python_lab2/vulnerable/gamehub
```

### 4.2. Создание виртуального окружения

Виртуальное окружение позволяет устанавливать библиотеки отдельно от системного Python.

Создай его:

```bash
python3 -m venv .venv
```

Активируй:

```bash
source .venv/bin/activate
```

После активации в начале командной строки появится `(.venv)`.

### 4.3. Установка зависимостей

```bash
pip install --upgrade pip
pip install -r requirements.txt
```

### 4.4. Инициализация базы данных

Выполни:

```bash
python init_db.py
```

Если база данных уже существует, программа предложит пересоздать её. Для чистого запуска введи `y`.

При успешной инициализации появится сообщение:

```text
Database created.
```

Будут созданы:

- `gamehub.sqlite3` — база данных приложения;
- `lab_data/public/guide.txt` — общедоступный учебный файл;
- `lab_data/private/secret.txt` — приватный учебный файл;
- таблица `lab_secrets` с искусственными данными для демонстрации SQL Injection.

Демонстрационные учётные записи:

| Логин | Пароль | Роль |
|---|---|---|
| admin | LabAdmin-ChangeMe-2026 | Администратор |
| player | PlayerDemo-ChangeMe-2026 | Обычный пользователь |

Эти данные предназначены только для локальной лаборатории.

### 4.5. Запуск приложения

```bash
python app.py
```

При успешном запуске Flask выведет адрес:

```text
http://127.0.0.1:5000
```

Открой его в браузере Kali Linux.

Для остановки приложения используй `Ctrl+C` в терминале, где запущен сервер.

## 5. Проверка SQL Injection

Для демонстрации SQL Injection предусмотрены две точки входа:

- форма авторизации `/login`;
- поиск по каталогу игр `/games`.

### 5.1. Проверка авторизации

Открой в браузере:

```text
http://127.0.0.1:5000/login
```

Введи в поле имени пользователя:

```sql
' OR 1=1 -- 
```

В поле пароля введи любое значение.

Отправь форму.

В уязвимой версии специально сформированный ввод изменяет условие SQL-запроса, позволяя продемонстрировать обход проверки пароля.

Дополнительный вариант:

```sql
admin' -- 
```

Он демонстрирует возможность обращения к записи администратора без проверки правильности пароля.

### 5.2. Проверка поиска игр

Открой:

```text
http://127.0.0.1:5000/games
```

В поле поиска введи:

```sql
%' UNION SELECT 1, name, value, 2024, 8.0, 'injected' FROM lab_secrets -- 
```

В уязвимой версии запрос может вернуть записи из учебной таблицы `lab_secrets`.

Ожидаемое значение для записи `flag`:

```text
GAMEHUB{un10n_b4s3d_5ql1_w0rk5}
```

Это искусственный маркер, созданный специально для лабораторной работы.

### 5.3. Проверка с помощью PoC

Открой второй терминал.

Перейди в каталог уязвимой версии и активируй окружение:

```bash
cd ~/python_lab2/vulnerable/gamehub
source .venv/bin/activate
```

Запусти проверку SQL Injection:

```bash
python exploits/exploit_sqli.py
```

Скрипт проверяет три сценария:

1. Обход авторизации.
2. Попытка входа в учётную запись администратора.
3. Получение данных из таблицы `lab_secrets`.

В конце выводится сводка результатов.

## 6. Проверка Path Traversal

### 6.1. Проверка обычного скачивания

Убедись, что приложение запущено.

Открой:

```text
http://127.0.0.1:5000/download/guide.txt
```

Должен скачаться общедоступный файл `guide.txt`.

### 6.2. Проверка обхода каталога

Для проверки используется специально созданный файл:

```text
lab_data/private/secret.txt
```

Он находится за пределами публичной директории `lab_data/public`.

Открой в браузере:

```text
http://127.0.0.1:5000/download/%2e%2e%2fprivate%2fsecret.txt
```

В уязвимой версии приложение может вернуть содержимое приватного учебного файла.

Ожидаемый маркер:

```text
GAMEHUB{p4th_tr4v3rs4l_r34ch3d_pr1v4t3_f1l3}
```

### 6.3. Проверка с помощью PoC

Во втором терминале выполни:

```bash
cd ~/python_lab2/vulnerable/gamehub
source .venv/bin/activate
python exploits/exploit_path_traversal.py
```

Скрипт проверит доступность обычного файла и несколько вариантов обхода каталога.

Для сравнения результатов обращай внимание на строки `ФАЙЛ ПРОЧИТАН` и `отказ`.

## 7. Запуск исправленной версии

После проверки уязвимой версии останови сервер сочетанием `Ctrl+C`.

Перейди в каталог исправленного приложения:

```bash
cd ~/python_lab2/fixed/gamehub
```

Создай отдельное виртуальное окружение:

```bash
python3 -m venv .venv
```

Активируй его:

```bash
source .venv/bin/activate
```

Установи зависимости:

```bash
pip install --upgrade pip
pip install -r requirements.txt
```

Создай отдельную базу данных:

```bash
python init_db.py
```

Запусти приложение:

```bash
python app.py
```

Исправленная версия также будет доступна по адресу:

```text
http://127.0.0.1:5000
```

**Почему используются отдельные базы данных?**

Уязвимая и исправленная версии по-разному хранят хеши паролей. Поэтому каждой версии нужна собственная база данных, созданная её собственным `init_db.py`.

Не копируй `gamehub.sqlite3` из одной версии в другую.

## 8. Проверка исправлений

Теперь повтори проверки на версии `Fixed`.

### 8.1. SQL Injection

Открой:

```text
http://127.0.0.1:5000/login
```

Повтори проверку с вводом:

```sql
' OR 1=1 -- 
```

В исправленной версии авторизация должна отклонить попытку входа с неправильным паролем.

Затем открой:

```text
http://127.0.0.1:5000/games
```

Повтори проверку с UNION-запросом из раздела 5.2.

Данные из `lab_secrets` не должны появиться в результатах поиска.

Можно также запустить PoC:

```bash
python exploits/exploit_sqli.py
```

Ожидаемый результат: скрипт не должен обнаружить успешную эксплуатацию SQL Injection.

### 8.2. Path Traversal

Открой:

```text
http://127.0.0.1:5000/download/guide.txt
```

Обычное скачивание должно работать.

Теперь повтори запрос:

```text
http://127.0.0.1:5000/download/%2e%2e%2fprivate%2fsecret.txt
```

В исправленной версии доступ к приватному файлу должен быть запрещён.

Ожидаемый HTTP-ответ — `404`.

Запусти PoC:

```bash
python exploits/exploit_path_traversal.py
```

Скрипт не должен обнаружить успешного обхода каталога.

## 9. Автоматическое тестирование

В обеих версиях проекта предусмотрены автоматические тесты на pytest.

### 9.1. Проверка Vulnerable

Останови сервер и выполни:

```bash
cd ~/python_lab2/vulnerable/gamehub
source .venv/bin/activate
python -m pytest -q
```

Тесты позволяют проверить функциональность приложения и продемонстрировать поведение намеренно уязвимой реализации.

### 9.2. Проверка Fixed

```bash
cd ~/python_lab2/fixed/gamehub
source .venv/bin/activate
python -m pytest -q
```

В исправленной версии защитные тесты должны проходить успешно.

Сравни результаты двух запусков: они позволяют убедиться, что внесённые исправления изменили поведение приложения.

## 11. Частые проблемы

| Проблема | Возможная причина | Решение |
|---|---|---|
| `externally-managed-environment` | Установка библиотек в системный Python | Создать и активировать `venv` |
| `ModuleNotFoundError` | Не установлены зависимости или не активировано окружение | Активировать `.venv` и выполнить `pip install -r requirements.txt` |
| `Address already in use` | Порт 5000 уже занят | Остановить предыдущий сервер |
| Не работает вход | Используется база данных другой версии | Пересоздать базу через `python init_db.py` |
| PoC сообщает, что приложение недоступно | Сервер не запущен | Запустить `python app.py` |
| `sqlite3: command not found` | Не установлен SQLite CLI | Выполнить `sudo apt install sqlite3` |
| Path Traversal возвращает 404 в Vulnerable | Неправильный URL или сервер запущен из другой версии | Проверить адрес и текущий каталог проекта |
