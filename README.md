# GameHub Security Lab

Учебное веб-приложение, разработанное на Python с использованием Flask, предназначенное для изучения распространённых уязвимостей веб-приложений, демонстрации способов их эксплуатации и рассмотрения методов защиты.

Проект содержит две версии одного приложения:

- **Vulnerable** — версия с намеренно оставленными уязвимостями.
- **Fixed** — версия с исправлениями, направленными на устранение обнаруженных уязвимостей.

Основная цель проекта — изучить причины возникновения уязвимостей, научиться демонстрировать их в контролируемой среде и понять принципы безопасной разработки веб-приложений.

## Установка и настройка

### Требования

- Linux (рекомендуется Kali Linux).
- Python версии 3.10 или новее.
- pip.
- Git.

### 1. Клонирование репозитория

Откройте терминал и выполните:

```bash
git clone https://github.com/Sanyokchek/python_lab2.git
cd python_lab2
```


### 2. Запуск уязвимой версии

Перейдите в каталог приложения:

```bash
cd vulnerable/gamehub
```

Создайте виртуальное окружение:

```bash
python3 -m venv .venv
```

Активируйте его:

```bash
source .venv/bin/activate
```

Установите необходимые зависимости:

```bash
pip install -r requirements.txt
```

Создайте базу данных и демонстрационные файлы:

```bash
python init_db.py
```

Запустите приложение:

```bash
python app.py
```

Откройте браузер и перейдите по адресу:

```text
http://127.0.0.1:5000
```

### 3. Запуск исправленной версии

Остановите предыдущий сервер сочетанием клавиш `Ctrl+C`.

Перейдите в каталог исправленной версии:

```bash
cd ../../fixed/gamehub
```

Создайте отдельное виртуальное окружение:

```bash
python3 -m venv .venv
```

Активируйте его:

```bash
source .venv/bin/activate
```

Установите зависимости:

```bash
pip install -r requirements.txt
```

Создайте отдельную базу данных:

```bash
python init_db.py
```

Запустите приложение:

```bash
python app.py
```

Приложение будет доступно по адресу:

```text
http://127.0.0.1:5000
```

Каждая версия использует собственную базу данных и виртуальное окружение. Рекомендуется запускать только одну версию одновременно, поскольку обе используют один локальный порт.

## Запуск и использование приложения

GameHub предоставляет игровой каталог с возможностью регистрации, авторизации, добавления отзывов и использования административных функций.

Демонстрационные учётные записи задаются в файле `init_db.py` соответствующей версии приложения.

База данных и демонстрационные файлы создаются локально при выполнении `init_db.py`.

## Реализованные уязвимости

В проекте рассматриваются две распространённые уязвимости веб-приложений.

### 1. SQL Injection — внедрение SQL-кода (CWE-89)

Уязвимость реализована в двух функциях приложения:

- Форма авторизации (`/login`).
- Поиск по игровому каталогу (`/games`).

В уязвимой версии пользовательский ввод непосредственно включается в SQL-запросы.

Это позволяет специально сформированным значениям изменять логику выполнения SQL-запроса.

Для демонстрации используется отдельная учебная таблица `lab_secrets`, содержащая искусственные данные. Это позволяет показать последствия SQL-инъекции без обращения к реальной пользовательской информации.

### 2. Path Traversal — обход каталогов (CWE-22)

Уязвимость находится в обработчике скачивания файлов:

```text
/download/<path:filename>
```

В уязвимой версии приложение формирует путь к файлу на основе пользовательского ввода, не проверяя должным образом, что итоговый путь находится внутри разрешённого каталога.

Это может позволить получить доступ к файлам за пределами публичной директории.

Для демонстрации используется искусственный приватный файл, создаваемый при инициализации проекта.

## Демонстрация эксплуатации уязвимостей (PoC)

В каталогах `exploits/` находятся Python-скрипты, предназначенные для демонстрации обнаруженных уязвимостей в локальном приложении GameHub.

**PoC (Proof of Concept)** — демонстрационный программный код, подтверждающий возможность эксплуатации определённой уязвимости.

### SQL Injection PoC

Демонстрация SQL-инъекции включает два сценария.

**Обход авторизации**

PoC демонстрирует, как специально сформированный ввод может изменить условие SQL-запроса при авторизации.

В уязвимой версии небезопасное формирование SQL-запроса позволяет продемонстрировать обход проверки пароля.

В исправленной версии используются параметризованные запросы, благодаря которым пользовательский ввод не может изменить структуру SQL-команды.

**Получение данных из демонстрационной таблицы**

PoC для поиска по каталогу демонстрирует, как небезопасный SQL-запрос может быть изменён таким образом, чтобы получить искусственные значения из таблицы `lab_secrets`.

Этот пример показывает, что SQL-инъекция может угрожать не только механизму авторизации, но и конфиденциальности данных базы.

В исправленной версии параметризованные запросы предотвращают подобное поведение.

### Path Traversal PoC

PoC для Path Traversal отправляет запрос к обработчику скачивания файлов с путём, который пытается выйти за пределы публичного каталога.

В уязвимой версии недостаточная проверка пути позволяет обратиться к демонстрационному приватному файлу.

В исправленной версии путь нормализуется и проверяется на принадлежность разрешённому каталогу.

Демонстрация позволяет сравнить поведение двух реализаций, используя только искусственные файлы, созданные самим проектом.

### Ожидаемые результаты демонстрации

| Уязвимость | Vulnerable | Fixed |
|---|---|---|
| SQL Injection при авторизации | Демонстрируется обход авторизации | Инъекция предотвращается |
| SQL Injection при поиске | Возможно получение искусственных данных из БД | Инъекция предотвращается |
| Path Traversal | Возможно обращение к приватному демонстрационному файлу | Доступ за пределами публичного каталога запрещён |

Все PoC-скрипты предназначены исключительно для локального приложения GameHub, запущенного по адресу `127.0.0.1:5000`.

Точные параметры запуска и особенности работы отдельных скриптов указаны в самих файлах и комментариях к ним.

## Ручная эксплуатация уязвимостей

Помимо автоматизированных PoC-скриптов, проект позволяет вручную продемонстрировать эксплуатацию уязвимостей через веб-браузер.

Все действия выполняются исключительно на локально запущенной уязвимой версии GameHub.

### 1. SQL Injection — ручная демонстрация

Уязвимость можно проверить через две функции приложения:

- Форму авторизации (`/login`).
- Поиск по игровому каталогу (`/games`).

**Авторизация**

1. Запустите уязвимую версию приложения.
2. Откройте страницу авторизации в браузере.
3. Введите демонстрационное SQL-условие `' OR 1=1 --` в поле имени пользователя 
4. Отправьте форму и сравните результат с обычной попыткой авторизации.
5. Повторите проверку на исправленной версии.

В уязвимой реализации пользовательский ввод может изменить логику SQL-запроса. В исправленной реализации параметризованные запросы предотвращают интерпретацию введённых данных как SQL-команд.

**Поиск по каталогу**

1. Откройте страницу игрового каталога.
2. Введите специально сформированное поисковое значение:
`%' UNION SELECT 1, name, value, 2024, 8.0, 'injected' FROM lab_secrets -- `
3. Отправьте поисковый запрос.
4. Сравните полученные результаты в уязвимой и исправленной версиях.

Демонстрация показывает, как небезопасное формирование SQL-запроса может повлиять на результаты поиска и доступность данных демонстрационной таблицы `lab_secrets`.

### 2. Path Traversal — ручная демонстрация

Уязвимость проверяется через функцию скачивания файлов.

1. Запустите уязвимую версию GameHub.
2. Откройте в браузере обычную ссылку на скачивание публичного файла:

   `http://127.0.0.1:5000/download/guide.txt`

3. Убедитесь, что файл успешно скачивается.
4. Для проверки Path Traversal используйте предусмотренный проектом демонстрационный запрос к приватному файлу:

   `http://127.0.0.1:5000/download/..%2Fprivate%2Fsecret.txt`

5. Если демонстрация успешна, браузер скачает учебный файл из приватной директории проекта.
6. Остановите уязвимую версию и запустите исправленную.
7. Повторите проверку с тем же адресом.

В уязвимой версии недостаточная проверка пути позволяет обратиться к файлу за пределами публичного каталога. Исправленная версия должна отклонить такой запрос.

### Сравнение результатов

| Проверка | Vulnerable | Fixed |
|---|---|---|
| SQL Injection при авторизации | Возможен обход проверки | Запрос обрабатывается безопасно |
| SQL Injection при поиске | Возможно получение демонстрационных данных | Инъекция предотвращается |
| Path Traversal | Возможен доступ к учебному приватному файлу | Запрос отклоняется |

**Важно:** ручные демонстрации выполняются только в локальной лабораторной среде на `127.0.0.1`. Используйте исключительно искусственные данные, созданные проектом.

## Исправления уязвимостей

В исправленной версии реализованы изменения, направленные на устранение обнаруженных проблем безопасности.

### Защита от SQL Injection

Вместо непосредственного объединения пользовательского ввода со строками SQL используются параметризованные запросы SQLite.

Пользовательские значения передаются отдельно от SQL-команды и рассматриваются как данные, а не как часть синтаксиса запроса.

Также улучшено хранение паролей: вместо обычного SHA-256 используется механизм хеширования паролей с индивидуальной солью.

### Защита от Path Traversal

В исправленной реализации путь к запрашиваемому файлу нормализуется, после чего проверяется, что он находится внутри разрешённого публичного каталога.

Для этого используются:

- `Path.resolve()` — получение нормализованного абсолютного пути.
- `Path.is_relative_to()` — проверка принадлежности итогового пути разрешённому каталогу.

Если путь выходит за пределы разрешённой директории, приложение отклоняет запрос.


Файл позволяет изучить изменения серверного кода, внесённые для устранения уязвимостей.

## Конфигурация

Flask использует параметр `SECRET_KEY` для криптографической подписи пользовательских сессий.

В проекте предусмотрена загрузка значения из переменной окружения:

```text
GAMEHUB_SECRET_KEY
```

Пример настройки в Linux:

```bash
export GAMEHUB_SECRET_KEY="your-random-secret-key"
```

Переменную необходимо задать перед запуском приложения.

Не добавляйте в публичный репозиторий настоящие секретные ключи, пароли и конфиденциальные настройки.

База данных и демонстрационные файлы создаются локально при выполнении `init_db.py`.
